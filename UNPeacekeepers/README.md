# UN Peacekeepers 0.3.6 alpha — complete alpha release

Based on release/0.3.4-alpha (`d43f2477`) with centralized quest completion, simplified automatic site clearance, individual guest stays and saved-quest repair. This is an experimental playable build for testing, not a claim that every scenario in the development document is finished. Target: RimWorld 1.6.4871, Harmony and VEF; Royalty for shuttle missions, Biotech for pollution. Managed DLL suitable for RimWorld on Mac M3.

## Package 1 — live quest displays

Uniform remaining time (game days, hours, minutes, rounded up), offer deadline or no fixed deadline, next-step text, persisted failure reasons, live active-first mission list in UN Central including old supply contracts and ultimatum. Existing saved failure reasons are unknown unless recorded; no retrospective assumptions. All original mission deadlines, guest rules, reward amounts, map cleanup and combat conditions are retained. All six development packages are integrated. The CI-base requires finalization with the exact approved assets.

## Package 2 — guest stay and evacuation

Live group countdown is the latest valid individual guest-stay timer, not a predicted shuttle arrival. It is unavailable until all required remaining guest timers are valid. Individual status includes bleeding, anesthesia, guest status, natural exit, shuttle request, landed, boarded and departed. The existing 24-hour stay is unchanged. Mobile guests have up to six game hours after their stay to exit before fallback; downed guests or guests with no exit route are eligible immediately after the stay. Blocked requests retry once per game hour. An interrupted stay resets; an invalid pickup is unloaded before reuse. Existing dispatched legacy shuttles retain their flow. Actual confirmed departure before the mission deadline remains required. These are compile/rule-tested changes; in-game shuttle and guest AI need testing.

## Package 3 — medical treatment

All original patients must be accounted for. A living, fully recovered patient still at the field hospital counts at completion, unless observed at home or already on the saved guest route. Home patients require full recovery, the unchanged 24-hour guest stay and confirmed departure. Mixed groups complete automatically when both sets satisfy their conditions. Field recovery is rechecked rather than irrevocably credited. Saved home-route IDs and existing guest records are preserved; historic home visits without saved evidence cannot be inferred. Individual medical displays use the actual recovery predicates, show bleeding, acute injuries, treatable illnesses, required limb/implant and anesthesia. No estimated healing time is invented. If a bionic scenario cannot safely provide the implant, it uses the existing normal-injury fallback and updates the description. No medical balance or reward change.

## Package 4 — military objectives and handover

Defense duration is shown before acceptance and counts down from first map generation, with protected civilian/structure and remaining enemy counts. Guards and attackers count as neutralized when dead, downed, player prisoners, or observed leaving the map into the world; confirmed flight is revoked on return. A weaponless but combat-capable pawn is not neutralized. Exact enemy IDs and confirmed deaths/exits are saved; missing references without proof are not automatic success. Elite arrest and ultimatum display target/pickup phases and require verified boarding and actual timely departure. Failed pickup requests are throttled to one game hour. Original deadlines, combat budget, rewards and cleanup remain unchanged. Actual AI and shuttle behavior still require game testing.

## Package 5 — supplies, optional offers and payouts

Required, delivered and missing quantities are shown separately in live mission and central views. Real delivery consumes only missing goods; exact validated completion is required. Optional offers have explicit acceptance expiry checks, no penalty for decline/expiry, a separate active count and direct Accept/Decline in both the choice letter and mission pool. Optional acceptance may select a valid home colonist; normal main acceptance conditions remain. Updated difficulty terms are shown before acceptance. New silver parcels use the exact quest ID, persist totals and dispatch status, and are retried hourly if safely blocked. A persisted pre-spawn uncertainty guard prevents ambiguous native/mod spawn outcomes from automatically paying twice; such payments are listed for review. Dispatch is not proof of landing or collection. Old unlinked parcels are retained without guessing their quest identity; old settled rewards are never automatically replayed. Reward amounts and mission durations unchanged.

## Package 6 — regression and release

CI checks the v0.3.5 cleanup implementation byte-for-byte, stable definitions and saved field names, all mission deadline boundaries, new reward-ledger guards, translations, DLL and archive. Follow-up base quantities use their original 30/90, stale pickup satisfaction is invalidated when the actual launch snapshot is invalid, and inconsistent/duplicate keyed parcels are held instead of replayed. Captured colony prisoners are not forced hostile by the local mission override. The approved asset overlay is applied separately and verified against the handover manifest. These checks do not run RimWorld: actual save/load, quest UI, guest/shuttle AI, pod landing, mod compatibility and native map removal require the in-game test checklist.

## Install

Install only the finalized `UN_Peacekeepers_v0.3.6-alpha.zip`. Do not install the GitHub Actions CI-base archive. The repository still has the older 20 armor PNGs; `tools/assets-approved-v033.json` records the approved handover hashes. `tools/finalize_approved.py` combines the verified CI-base with the user's approved v0.3.2 ZIP, verifies all 24 asset hashes, and produces the full installable ZIP. Direct binary synchronization to GitHub remains outstanding. Extract `UNPeacekeepers` into the game's Mods folder, replacing the previous mod folder. Keep a copy of the old mod and save. Load a COPY of your save for alpha testing. No game DLLs are shipped. Existing v0.2.9 supply orders retain their original handover and rewards; new orders use the new pool.

## Core implementation

- One local UN Central console button, no power/pawn required. Four live, movable tabs: overview, prison, history, rules. The window does not force pause or camera lock. Settings only in the game's mod settings. Normal pawn-operated comms provides aid and mission acceptance.
- Persistent ten-slot offer pool: 10 ordinary at 0..49; 5 ordinary/5 advanced at 50..79; 5 ordinary/4 advanced/1 elite at 80+. Slots may remain empty if no valid faction/site/leader exists or their individual three-day refill is pending. Maximum five accepted main missions (legacy supply orders count); optional follow-ups do not count. Offers do not reroll when the window opens.
- Ten days without accepting an order costs 10 UN goodwill, stopping at +50. Migration starts a fresh clock. Existing goodwill, prison assessment, raids/aid, equipment authorization, packageId and original DefNames are preserved.
- Ordinary/advanced/elite rewards: 1,500/5,000/10,000 base silver and +10/+20/+30 goodwill. The supported valid non-UN faction receives the same requested goodwill subject to its own hard diplomacy rules. Excess earned UN goodwill above +100 becomes 100 silver per point. Silver rewards and UN goodwill overflow arrive in native drop pods at a safe home-map landing spot near the orbital trade area. The dispatch letter links to the landing spot. Pending amounts are saved and retried until dispatch, with no replay of dispatched payments.
- Separate 25–500% mission difficulty. Existing offers update shown terms before acceptance when the setting changes; accepted contracts retain their values. No reroll of goods or targets. UN raid strength remains separate. +30 elite goodwill is a planning default.

## Seven core mission flows

Accept through normal UN radio contact or the native quest log with an eligible colonist. Offers show recipient, requirements, destination tile, risk and reward. Temporary sites are created only on acceptance.

1. Supply delivery: one ordinary or two/three advanced goods types. Carry real goods to the destination. At an existing friendly settlement, use the caravan handover command on its tile. At a temporary site, use the marked handover point, bringing colonists and goods within eight cells; a caravan can also hand over on the site's tile. Partial deliveries persist; only full delivery pays.
2. Medical assistance: all patients must recover from acute injuries and immunizable illness and be free of vanilla anesthesia. No room/bed/temperature condition or manual completion button. Optional basic ward remains. Field and home treatment may be combined. Field patients must be alive and fully recovered at completion; patients transported to the requesting home map each stay as guests for 24 game hours after full recovery, then depart normally or by pickup shuttle. 15% of medical offers are single-patient cases requiring a specific vanilla bionic arm/leg at the missing limb, with a matching item and medicine at the site. Ordinary/advanced and rescue patients have mixed small and heavier wounds. No custom anesthesia or surgery.
3. Evacuation: contact the exact civilians at the handover point, transport them to the requesting home map, stop bleeding and wait out anesthesia, then each stays one game day as a guest and must depart safely. No 80% completion.
4. Prisoner rescue: recover the exact people from a guarded camp and bring them home, stabilize them, then each stays one game day as a guest before departure. Destroying the base is not an objective; reaching and rescuing the targets is sufficient.
5. Protection: preserve all named people and the handover installation for the agreed duration and defeat/incapacitate the mission attackers. Initial implementation uses a single budgeted wave.
6. Intervention: a temporary conflict map uses genuinely hostile existing factions, with supported defenders and UN allies. Enemy budget is storyteller ×1.5 × mission difficulty; supported defenders use 25%, UN support uses 10%. No global faction relation rewrites.
7. Elite arrest: reserves an available real hostile faction leader, never a clone. Capture that exact person alive, stabilize bleeding, return home as prisoner and load the UN shuttle. Budget ×3; UN support 10%. Offers can be unavailable when no suitable unreserved leader exists.

Shuttle rewards require successful execution of the physical launch, not merely the earlier loading signal. Dead/missing required people or expiry cause failure (−5). Cancellation after acceptance also costs −5; this is the explicit alpha default, with confirmation. Already handed-over goods are not refunded. Temporary civilian custody restores original factions on cleanup. Finished temporary sites and their world markers are removed automatically once player units, prisoners and other active quest targets have left and native safety permits. Abandoned cargo, ordinary NPCs and loot do not prevent closure; anything left behind can be lost. Native checks still protect incoming transports, pocket maps and blocking buildings. Existing settlements are not removed. Saved mission completion evidence is reconciled on load; ambiguous legacy payments are not repeated. The guest timer resets on relapse, and existing dispatched shuttles keep their old flow.

After a medical/protection success, one optional medicine delivery may be offered at a separate reserved tile. Its own temporary camp is created only on acceptance. Existing unaccepted follow-ups sharing an old camp migrate to a separate tile when available; accepted legacy follow-ups retain their original target and progress. It expires unaccepted after three days without penalty. If accepted it has its own full tier reward/deadline/failure result, no main slot, and cannot recurse. The main result is independent. A native choice letter shows the actual quantities, silver, goodwill, remaining acceptance deadline and mission duration, with direct Accept, Decline and Postpone buttons. Existing unaccepted offers receive the new letter on load without changing their expiry. A valid home-map colonist is selected for acceptance; all existing acceptance checks remain.

## Conventions and pollution

Existing prison penalties/recovery stay unchanged. New reliable event hooks cover deliberately ordered unprovoked pawn attacks, deliberate killing of already downed opponents or noncombatant unarmed civilians, execution, abuse, harvest/removal intent, prisoner recruitment, enslavement, unauthorized UN gear, vanilla toxic-gas release and toxic-gas projectiles. Highest applicable aggression penalty is counted once per encounter window, not per bullet. Pre-damage status prevents counting a killing blow that merely downs an active fighter as an execution. Defence and mission combat authorization are local to registered attackers.

Own pollution is tracked only through proven source contexts: owned machine emission, traceable waste decay and player-instigated explosion cell processing. Previously polluted cells and unassigned/mod-bypassed effects are not attributed retroactively. Cleaning removes ownership. One weighted periodic penalty covers loaded home maps every three days. Explicit caravan waste abandonment accumulates in groups of five, preserving the remainder. Safe storage/normal disposal is not charged.

Prisoner experiments and proven fatal starvation are added in 0.3.1. Completed player-owned gene extraction, completed softscan, destructive ripscan (including fatal cancellation), and configured prisoner surgeries such as InstallMindscrew cost 20 points. Only a confirmed actual death from the explicitly lethal Malnutrition culprit, without a damage event, costs 30. Ordinary diseases, blood loss, regeneration coma and deathrest never automatically count as negligent deaths. The optional XML rule list allows exact RecipeDef or direct-target AbilityDef names and scanner ThingDefs to be added; unconfigured actions are not treated as experiments. A configured surgery that actually enters its worker is counted even if surgery fails; the overlapping generic surgery or harvest penalty is suppressed for that recipe. Unknown or ambiguous causes are not charged. Existing penalties, journal, recovery and ultimatum logic are reused. The new hooks are compile-tested but not exercised in-game. Unknown mod events are conservatively ignored. The event hooks are not a guarantee of coverage for every modded weapon, surgery, recruitment mechanism or attack source.

## Ultimatum

100 unconsumed raw crime points within ten days create a separate mandatory three-day quest, independent of current goodwill/clamping and the five slots. Select a leader in UN Central. The deadline runs even without selection; a locked target cannot be swapped. Successful living shuttle surrender grants +20; refusal/expiry costs −20 and schedules a targeted capture detail. If no leader has been selected, the arrest remains pending and the UI permits selection. Triggering points are consumed once. Capture troops pursue the selected person with clubs and kidnap if downed, rather than receiving a colony-destruction job; combat can still be lethal. A new regular UN raid waits while the capture operation is active, without resetting its timer.

## Validation and unfinished scope

CI compiles the managed DLL and runs pure rule tests plus localization, definition, XML and repository-asset checks. The finalized installation archive independently checks all approved asset hashes, including 20 exact PNG replacements. Static tests are NOT engine integration tests. No real save load or full in-game mission has been run here. Test the three-way bridge between quest log, caravan/map objectives and shuttle carefully on a copied save.

Still outside this first alpha: full scenario weights and complications, all four fully furnished UN base variants, the complete optional-combination matrix, multi-wave protection, existing-base/Custom Base Framework combat placement, additional medical variants and dedicated vehicle-framework arrival support. Vanilla caravans and site visit paths are used; modded vehicles/transport need separate verification. Ordinary missions currently have no random combat complication. NPC conflicts use existing hostility rather than a diplomacy-mod war API. Forecasts are current-state previews, not guarantees.

Compatibility with direct field writes, mods replacing native combat/transport behavior, and the entire supplied mod list is not guaranteed. Do not downgrade/remove this version after saving its new quest/component classes. All equipment definitions are unchanged. The final archive uses the 20 approved armor PNGs from the previous installed ZIP plus the other four original assets, without regenerating or modifying graphics. The repository asset synchronization is still open; do not install the CI-base archive.
